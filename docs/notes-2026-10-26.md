## Decisions

- Blank slate on `@fractal/sdk`. Fractal's API stays unchanged. Reuse `@fractal/ui` only where a component already fits.
- Polychrome connects through its own paired, full-control session, so it can send messages.
- Messages render with react-markdown directly.
- What done means: `QUALITY.md`.
- Backlog: `issues/`, one file per issue. New ideas start as `idea`.
- Direction: `VISION.md`.

## What Fractal has and doesn't have

- **Has:**
  - schedules (interval, daily or weekly), which start missions
  - checks on parts of a mission (commands that must pass)
  - person asks, the alerts, with recorded answers
  - missions that start other missions (`uses-mission`)
  - GitHub watching for a specific PR or issue
- **Doesn't have:**
  - an issue tracker or backlog
  - a repo-wide event trigger, like "on any new PR"
  - a chief-of-staff or orchestrator role
- **Agent constraints only apply inside missions.** Standing instructions for an agent belong in its workspace files.
- **Phone access:** the survey (docs/survey.md §1) found three ways in: the daemon's local web session, the Vite dev proxy, and a Tailscale-serve publisher. The encryption details are still to be confirmed.
